# ADR 0003: GitHub Actions の AWS 認証に OIDC を採用する

## ステータス

承認済み（2026-08）

## 背景

GitHub Actions から S3 へのファイル同期と CloudFront のキャッシュ削除を行うため、
AWS の認証情報が必要になる。

## 検討した選択肢

**IAM ユーザーのアクセスキーを GitHub Secrets に保存** — 最も一般的な方法。
設定が簡単で参考資料も多い。ただし長期有効な認証情報がリポジトリ設定に
保存され続けることになる。

**OIDC による一時認証** — GitHub が発行する短命な ID トークンを AWS が検証し、
`sts:AssumeRoleWithWebIdentity` により一時的な認証情報を発行する方式。

## 決定

**OIDC を採用する。**

## 理由

アクセスキー方式は、鍵そのものが存在し続けることが根本的な弱点である。
ローテーションを怠れば無期限に有効であり、誤ってログや設定ファイルへ
出力されれば即座に悪用され得る。

実際、本プロジェクトの構築過程でローカル環境のアクセスキーを
誤って外部へ露出させる事象が発生した（該当キーは即時無効化済み）。
長期認証情報を持つこと自体がリスクであることを実体験として認識している。

OIDC ではキーが存在しない。実行のたびに一時的な認証情報が発行され、
セッション終了後は失効する。漏洩し得る対象そのものを排除できる。

## 実装上の要点

**信頼ポリシーの条件指定が最重要である。**
