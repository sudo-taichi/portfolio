## 概要

1,000名規模のエンタープライズ環境における保守運用およびインシデント対応を担当。
日々の問い合わせ対応にとどまらず、運用プロセスそのものの標準化を推進した。

**実績（14ヶ月間）**

| 指標 | 実績 |
|---|---|
| 一次対応 SLA 達成率 | **100%**（参画以降、継続維持） |
| インシデント・問い合わせ解決 | **321件** |
| システム障害対応・復旧 | **23件** |
| 作成・整備した手順書 | **約 100件** |

**一次対応 SLA の基準**

| 重要度 | 応答期限 |
|---|---|
| 高 | 3時間以内 |
| 中 | 1営業日以内 |
| 低 | 3営業日以内 |

## 課題

運用チームにおいて、タスク管理と障害対応が担当者ごとに属人化していた。
情報共有に遅延が生じ、対応品質にもばらつきがある状態。

過去にも管理手法の見直しは試みられていたが、
現場の負担が増えて形骸化するという課題を抱えていた。

## 取り組み

### 運用管理フローの設計と定着

管理手法を根本から見直し、現場の負担にならない実用的なフローを独自に設計。
ルールを作って終わりにせず、**関係各所との合意形成を図りながら
運用として定着するまで伴走**した。

形骸化を防ぐことを最優先に置き、実際に回る粒度まで落とし込んでいる。

### トラブルシューティング手法の体系化

発生した個別事象を分析し、事象ごとの最適な解決策と調査手順を確立。
確立した手順を標準的な運用フローとしてドキュメント化した。

### スクリプトによる Active Directory 情報抽出の自動化

従来手作業で行っていた AD のユーザー・端末情報の抽出について、
データを一括取得・エクスポートする自動化スクリプトを開発。

### 継続的な手順書整備

業務規模の大小を問わず、あらゆる作業プロセスの可視化とドキュメント化を推進。
担当期間中に約100件の手順書を作成・整備した。

後任者が迷わず安全に実務を遂行できることを基準に品質を設定している。

## 成果

- 最重要 KPI である一次対応 SLA（重要度高：3時間以内）において、
  **参画以降 100% の達成率を継続維持**
- 14ヶ月間で321件のインシデント・問い合わせを解決し、
  類似事象発生時に迅速に対応できる基盤を構築
- 14ヶ月間で23件のシステム障害対応・復旧を完遂
- 自動化により手作業の工数を削減し、ヒューマンエラーを排除。
  アカウント棚卸しやセキュリティ監査業務の効率化を実現
- 属人化を排除し、担当者に依存しない一定品質の対応体制を確立

## 担当業務

- Entra ID / Intune 管理下 PC の状態確認、同期実行、サインインログ調査
- 条件付きアクセスのエラー対応、ネームドロケーション編集
- USB デバイス制御のホワイトリスト登録
- アプリケーション証明書の更新
- EDR / SASE / SWG 製品の不具合調査とベンダーへの問い合わせ
- 脆弱性診断の事前設定確認および失敗サーバのトラブルシューティング
- ファイルサーバの権限管理（NetApp）
- Active Directory の情報取得、GPO の作成・検証
