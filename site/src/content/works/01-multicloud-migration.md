## 概要

Azure 上に設計・構築した勤怠管理システムの基盤を、GCP 環境へ再現するプロジェクト。
24時間稼働の Java Web アプリケーションおよびバッチ処理基盤を対象とした。
設計・構築からドキュメント整備までを含め、全体で2ヶ月で完了させた。

## 課題

異なるクラウド間での環境再現には、サービス仕様の差異を都度調査する必要があり、
工数が読めない。またチーム内で設計方針やコーディング規約が統一されておらず、
担当者ごとに実装が分かれる属人化のリスクを抱えていた。

## 取り組み

Gemini の **Gem 機能**を用いて、インフラ構築サポート用のカスタムエージェントを作成。
Azure 環境の設計仕様と、GCP 向けに作成した Terraform コードをナレッジとして登録し、
チーム全体へ展開した。

Gem には以下を担わせた。

- 既存コードを踏まえた GCP 向けリソース定義の生成
- Azure と GCP のサービス対応関係の即時参照
- コーディング規約に沿った実装のレビュー

あわせて、マネージドサービスではなく IaaS 上にデータベースを構築するなど、
個別要件に応じた柔軟な設計判断も行った。

## 成果

- Azure で手動構築した環境の設計知見をもとに、GCP 側では Terraform による
  コード化を実施。手動構築で得た理解を IaC へ落とし込む形で移行を進めた
- **構築フェーズを約2週間で完遂。** Gem による支援で、
  サービス仕様の調査工数を大幅に圧縮した
- 設計方針とコーディング規約の標準化を実現し、属人化を排除
- 設計書・手順書を含むドキュメントまで整備し、全体を2ヶ月で完了
- ナレッジが Gem に蓄積される仕組みとなり、再現性の高い情報共有体制を確立

## 技術構成

| 領域 | 採用技術 |
|---|---|
| IaC | Terraform |
| AI活用 | Gemini（Gem によるカスタムエージェント） |
| コンピュート | Compute Engine（Ubuntu LTS） |
| アクセス制御 | Identity-Aware Proxy (IAP) / VPC ファイアウォールルール / サービスアカウント |
| プロセス管理 | systemd / systemd timer / cron |
